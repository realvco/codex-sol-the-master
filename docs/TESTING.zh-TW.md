# 測試與回到預設設定

<p align="center"><a href="./TESTING.zh-TW.md" style="text-decoration: none;">🇹🇼 繁體中文</a> · <a href="./TESTING.md" style="text-decoration: none;">🇬🇧 English</a></p>

請在新的 Codex task 中，以無害的唯讀工作執行測試，並記錄客戶端實際顯示的證據。

## 0. 測試前置與證據規則

開始前確認目前使用的 Codex 執行檔、`$CODEX_HOME`、自訂 Agent 目錄與客戶端版本。
使用新的 task，避免舊 Session 的提示或快取路由被誤認為目前設定。

每次正向測試都記錄：task 身分、實際子代理、模型、推理強度，以及客戶端可顯示的
service-tier 狀態。如果沒有 tier 訊號，記錄「service tier 未觀測到」，不能自行
推論為 Standard 或 Fast。

## 1. 基準測試

在使用暗號前：

1. 執行 `/status` 或客戶端對應指令。
2. 記錄主代理模型、推理強度、速度／tier 與 task 身分。
3. 使用唯讀任務，避免路由失敗時修改專案檔案。

## 2. 正向測試

在兩個獨立 task 中，分別使用以下完整暗號：

```text
有請高手處理。請讀取 README.md 並回報標題，不要修改任何檔案。
```

```text
恭請高高手處理。請讀取 README.md 並回報標題，不要修改任何檔案。
```

預期證據：

- 實際建立的是自訂 Agent `sol_high` 或 `sol_xhigh`。
- 模型是 `gpt-5.6-sol`。
- 推理強度分別是 `high` 或 `xhigh`。
- 沒有要求 Fast。
- service-tier 只在客戶端實際顯示時回報。

正向結果必須來自真正的子代理，而不是主代理模仿 Sol 的回答。主代理應等待子
代理回報後，再整理結果給使用者。

## 3. 負向與碰撞測試

以下情況都不應建立自訂 Agent：

- `有請高手處理嗎？` 作為問題或引用，而不是主動指令。
- 只輸入 `高手處理` 或 `高高手處理`。
- 翻譯、解釋、編輯文件時提到任一暗號。
- 只說「請用更深的推理」或「使用更強模型」。

路由守門規則是逐字精確匹配，不得把近似句自動「修正」成有效暗號。

## 4. 同一任務出現多個暗號

如果同一項任務同時有效指定多個暗號，預期只使用 `sol_xhigh`，不讓兩個 Agent
重複執行相同工作。只有使用者清楚切分互不重疊的子任務時，才可分別委派。

## 5. 回到預設設定

子代理回報後：

1. 確認子代理結果已回到原本的主 task。
2. 在主 task 再執行 `/status`。
3. 確認沒有自訂 Agent 持續保持啟用。
4. 開一個不含任何暗號的新 task，確認使用 App 當前選定的主代理設定。

這只能驗證單次授權範圍，不能保證所有未來客戶端都提供相同的 tier 遙測。

## 6. 可選的父代理速度隔離測試

如果客戶端提供足夠遙測，可先把父代理設為 Fast，再執行兩個正向測試。確認子
代理沒有靜默要求或繼承 Fast，並在子代理結束後確認父代理回到原本速度。如果
客戶端無法顯示子代理的獨立速度，請記錄為可觀測性限制，不要為了測試而永久
修改整個 Codex App 的速度設定。

## 7. 測試回報範本

```text
客戶端／版本：
父代理 task 與設定：
使用的完整暗號：
實際子代理：
模型：
推理強度：
Service tier 或 Fast 狀態：
修改檔案：
執行的檢查：
回到預設結果：
未觀測行為或阻礙：
```
